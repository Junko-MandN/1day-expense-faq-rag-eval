# 社内FAQ AIの回答品質を比較する — API × RAG × Evals

## 1. プロジェクト概要

社内の経費精算FAQを題材に、情報の与え方によってAIの回答品質がどのように変わるかを検証した。

単に正解率を比較するのではなく、以下の3つの観点から評価した。

- **Accuracy（正確性）**：あらかじめ設定した期待回答と一致しているか
- **Grounding（根拠への忠実さ）**：与えられた規程の内容に沿って回答しているか
- **Abstention（適切な回答保留）**：根拠が不足している場合に、推測で断定せず、適切に回答を保留できるか

検証には、架空の経費精算規程と10問のテスト質問を使用した。

## 2. 検証方法

同じ10問に対して、次の3方式で回答を生成し、比較した。

| 方式 | 情報の与え方 | 検証の目的 |
|---|---|---|
| A：モデルのみ | 社内規程を与えない | モデル単体での回答を確認する |
| B：規程全文 | 経費精算規程の全文を与える | 規程情報を与えた場合の回答品質を確認する |
| C：簡易RAG | キーワード検索で関連する規程箇所を取得して与える | 必要な情報を検索して回答する方式を確認する |

各方式の回答を、正確性・根拠への忠実さ・適切な回答保留の観点から手動で評価した。

本検証では、キーワード検索による簡易的なRAGを使用している。高度な検索手法や本番環境向けの構成を評価したものではない。

## 3. 検証結果

### 3.1 集計結果

| 評価指標 | A：モデルのみ | B：規程全文 | C：簡易RAG |
|---|---:|---:|---:|
| 正確性 | 4/10（40%） | 10/10（100%） | 8/10（80%） |
| 根拠への忠実さ | 1/10（10%） | 9/10（90%） | 10/10（100%） |
| 適切な回答保留 | 7/8（87.5%） | 1/2（50%） | 2/2（100%） |
| 合計トークン数 | 2,890 | 9,352 | 4,432 |

※正確性は、設定した期待回答との一致を評価した結果である。期待回答自体の妥当性や、規程に明記されていない事項の扱いは、別途考慮する必要がある。

※回答保留の分母は、評価対象外の質問を除いた件数であり、方式ごとに異なる。そのため、他の指標と同じようには単純比較できない。

※Cの適切な回答保留2/2のうち、Q5の保留は、検索漏れの影響を含む（4章を参照）。

### 3.2 結果から分かったこと

**A：モデルのみ**

正確性は40%で、会社固有のルールを問う質問に対して、一般論で回答したり、社内規程の確認を促したりするケースが見られた。

社内FAQでは、モデル自体の能力だけでなく、必要な社内情報を適切に与えることが重要だと考えられる。

**B：規程全文**

期待回答との一致率は100%で、3方式の中で最も高かった。一方、根拠への忠実さは90%だった。

規程全文を与えていても、規程に明記されていない事項を断定したり、条件付きの記述を断定的に言い換えたりする可能性がある。

**C：簡易RAG**

正確性は80%、根拠への忠実さは100%だった。今回の検証では、検索した規程の範囲に沿って回答する傾向が見られた。

一方、必要な情報を検索できなかった場合や、検索結果だけでは判断できない場合には、回答の不足や解釈の問題が残る。

期待回答と一致しなかった2問（Q5、Q6）の原因は `analysis.md` にまとめた。Q5は検索漏れと規程の曖昧さが重なったケース、Q6は検索で必要な情報が取れていたが、回答で注意点が省略されたケースである。

## 4. 個別質問から得られた重要な学び

### Q5：宿泊費の上限を超える場合

質問は「1泊15,000円のホテルは、事前に所属部門長の承認を得れば精算できますか？」というものだった。

規程には、国内宿泊費の上限が1泊12,000円であること、上限を超える宿泊が必要な場合は予約前に所属部門長の承認を得ること、承認なしで超過した分は原則精算できないことが記載されている。一方、事前承認があった場合に超過分を精算できるとは明記されておらず、承認の基準も書かれていない。あえて曖昧さを残した検証ケースである。

- **B（規程全文）：** 「はい、…事前に所属部門長の承認を得れば精算できます。（第4章 宿泊費の規定による）」と言い切り、根拠として第4章を示した。しかし、第4章に承認後の精算可否は明記されていない。規程にない結論を、規程を根拠にして断定した。
- **C（簡易RAG）：** 承認に関する行（「上限を超える宿泊が必要な場合は、予約前に所属部門長の承認を得る」）が、検索キーワード（宿泊費・精算・ホテル）と一致せず、Cには渡されなかった。そのため、「事前に所属部門長の承認を得れば」については規程に明記されていないと回答した。渡された情報の範囲では妥当だが、「渡された行にない」ことを「規程にない」と表現しており、規程の曖昧さを指摘したわけではない。

この結果から、次のことが分かった。

- 期待回答との一致だけでは、根拠に忠実な回答かどうかを十分に評価できない。
- 検索の漏れは、モデルが保留した回答のように見える。原因を調べるには、実際に渡された規程行を確認する必要がある。
- 規程そのものに曖昧さがある場合、AIの回答品質だけでなく、規程の記述を明確にすることも重要になる。

詳細は `analysis.md` を参照。

### Q10：証憑に不備がある場合

規程には、申請内容や証憑に不備がある場合、確認・修正が完了するまで支払いが保留されることがある、と記載されている。

- Bは「支払いが保留されます」と断定した。
- Cは「支払いが保留されることがあります」と、規程の条件付きの表現を維持した。

この例から、結論が大きく外れていなくても、規程にある条件や確実性の程度を変えてしまうことが、回答品質上の問題になり得ると分かった。

この違いは、3つの評価指標では十分に捉えられない。評価表（`evaluation.csv`）では、結論が合っているため、Bの根拠への忠実さを1とし、備考にのみ記録した。「規程の条件や確実性の程度を保持したか」を、別の評価観点として追加する必要がある。

## 5. 考察

今回の結果では、規程全文を与えた方式Bが期待回答との一致率で最も高い結果となった。一方、根拠への忠実さでは方式Cが高い結果となった。

ただし、方式Bと方式Cのどちらか一方が常に優れていると結論づけることはできない。

実務で社内FAQ AIを設計する際には、少なくとも次の点を考慮する必要がある。

- 必要な社内情報を適切に検索・提供できること
- 回答が規程の記述と一致していること
- 規程に明記されていない内容を推測で断定しないこと
- 判断できない場合に、適切に回答を保留し、担当部署への確認を促せること
- 規程そのものに曖昧さや不足がないかを確認すること

正確性だけでなく、根拠への忠実さや回答保留も含めて評価することが、社内FAQ AIの品質を考えるうえで重要だと考えられる。

## 6. 検証の限界

本検証には、以下の限界がある。

1. **質問数が少ない**  
   10問のみの検証であり、質問の種類や難易度が変わった場合にも同じ傾向になるとは限らない。
2. **評価に期待回答と手動判定を使用している**  
   期待回答との一致を正確性として評価しているため、期待回答自体が曖昧な場合には評価結果にも影響する。また、手動評価には判定者の解釈が含まれる。
3. **検索方式が簡易的である**  
   キーワード検索を用いた簡易RAGであり、意味検索、検索結果のランキング、検索漏れへの対策などは十分に検証していない。
4. **実運用環境を検証していない**  
   利用者数、応答速度、運用コスト、権限管理、機密情報の取り扱い、継続的な規程更新などは今回の評価対象外である。
5. **回答保留の評価対象が少ない**  
   回答保留の評価件数が方式ごとに異なるため、今回の割合だけで保留能力の優劣を判断することは難しい。

## 7. 今後の改善案

今後は、以下の順に改善・検証を進める。

1. **評価基準の明確化**  
   期待回答との一致、規程との整合性、条件の保持、適切な回答保留を分けて評価する。特に、規程に明記されていない内容を断定した場合の判定ルールを明確にする。
2. **テスト質問の拡充**  
   明確に回答できる質問、規程に情報がない質問、複数の規程を参照する質問、規程の記述が曖昧な質問などを追加する。
3. **検索品質の改善**  
   キーワードの同義語対応、検索対象の分割方法、取得する情報量などを改善し、必要な規程箇所が取得できるかを検証する。
4. **回答保留と確認導線の検証**  
   根拠が不足している場合に、推測で回答するのではなく、不明点を説明して経理担当者などへの確認を促せるかを評価する。
5. **運用面の評価**  
   回答品質だけでなく、トークン使用量、コスト、応答時間、規程更新時のメンテナンス性も比較する。

## 8. 結論

本検証では、同じ10問に対して、モデルのみ、規程全文、キーワード検索による簡易RAGの3方式を比較した。

規程全文を与える方式は期待回答との一致率が最も高く、簡易RAGは根拠への忠実さで高い結果となった。また、規程に明記されていない事項を断定する問題や、条件付きの記述を断定的に言い換える問題も確認できた。

今回の検証から、社内FAQ AIの品質を評価する際には、正解率だけでなく、根拠への忠実さ、適切な回答保留、規程そのものの明確さをあわせて考慮する必要があると分かった。

ただし、これは10問による小規模な検証結果であり、追加の質問と評価基準の改善によって再検証する必要がある。
